# Decision record — ARPA issue #12

## Selected integration alternative

**Informative KYA-OS adapter/profile.**

The executable corpus supports consuming externally verified KYA-OS runtime evidence through a representation-neutral boundary while ARPA independently retains recognition, delegator competence, scope, lifecycle, historical evaluation, authority-conflict and enforcement-state decisions.

## Rejected for this tranche

- **KYA-OS as an ARPA core dependency:** rejected because proof format, identifier representation and host binding are not sources of ARPA governance authority.
- **Normative generic external-evidence interface:** deferred because one profile is insufficient evidence of a stable protocol-neutral abstraction.
- **Conceptual alignment only:** rejected because the current ARPA conformance machinery can exercise the authority boundary mechanically without changing the normative core.

## Residual uncertainty

The corpus models the verified/unverified proof result as an external input; it does not implement or independently validate KYA-OS cryptography. It therefore proves ARPA-side composition semantics, not live interoperability or KYA-OS conformance.
